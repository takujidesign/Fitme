# Round 9 tasks for Codex — anatomy-style exercise visuals

Same rules as earlier CODEX_TASKS files (static ES modules in `app/`, `L()` + zh/ja/vi, new files in `SHELL` of `app/sw.js` without touching the `VERSION` line, 375px, both themes, offline, backward-compatible state, tests). No worker changes.

The owner wants exercise visuals like a classic anatomy fitness illustration: a muscular grey figure on the equipment, **target muscles shaded red**, a **Start** and a **Finish** pose side by side, and **curved red arrows** showing the direction of movement (e.g. incline dumbbell press: dumbbells at chest → arms extended). We cannot copy commercial illustrations, so do both parts below.

## Part A — upgrade our own animated figure (all 40 exercises, no external assets)
- `app/js/figure.js`: render the mannequin with anatomical detail: muscle-belly shapes (pecs, delts, biceps, triceps, forearms, abs/obliques, lats/traps, glutes, quads, hamstrings, calves) drawn as shaded paths attached to the existing bones, light grey body with soft shading, dark shorts, darker equipment. Must stay smooth at 60 fps on a mid phone; keep the IK and props.
- Highlight target muscles: use `exerciseMuscles(EX[id])` from `app/js/muscle-map.js` — primary muscles red (`--muscle-primary`), secondary lighter red/orange (`--muscle-secondary`); tokens defined for light and dark themes.
- Movement arrows: for each exercise, a curved arrow along the path of the moving end effector (hands or hips/feet) between the start and end keyframes, drawn in red with an arrowhead; fades in/out with the rep. Derive from the pose keyframes automatically; allow per-exercise override in `exercises.js` (`arrow: {joint, bend}`).
- Start / Finish view: in the exercise sheet add a toggle "แอนิเมชัน / เริ่ม–จบ". The Start–Finish view shows two static frames side by side (first and peak keyframe) with labels "เริ่ม" / "จบ" and arrows — like the reference layout. Thumbnails in lists keep the animation.
- Muscle map (`muscle-map.js`): replace the boxy rectangles with a proper front/back anatomical silhouette drawn as SVG paths (own drawing, or adapt Anatome under Apache-2.0 with attribution already in credits). Same region ids, same accessibility (focusable, labels), same heat colours.
- Respect `prefers-reduced-motion`: show the Start–Finish view instead of looping animation.

## Part B — AI-generated illustrations pipeline (owner runs it with their own key)
The owner has a kie.ai account. Claude/Codex never handle the key; the script reads it from the environment.
- `scripts/illustrations/prompts.json`: for each of our 40 exercises (and an optional list of the 150 most common Free Exercise DB ids), `{ id, start, finish }` prompt texts built from one shared style prompt: "anatomical fitness illustration, muscular grey-skinned male figure with visible muscle definition, black shorts, barefoot, white background, clean 3/4 view, {equipment} in white/black, target muscles {muscles} highlighted in red, no text, no logo, consistent style" + the pose description for start/finish. Add a female variant flag for later (not generated by default).
- `scripts/illustrations/generate.mjs` (Node 22, no secrets in the repo):
  - Reads `KIE_API_KEY` from env; `KIE_MODEL` (default `gpt-image-2-text-to-image`, overridable — the owner will confirm the exact model id in the kie.ai Playground), `KIE_INPUT` JSON template for extra model fields (e.g. aspect ratio `1:1`, size), optional `KIE_REF_IMAGE_URL` + `KIE_REF_FIELD` to pass a reference image for style consistency.
  - API: base `https://api.kie.ai`, header `Authorization: Bearer $KIE_API_KEY`; create with `POST /api/v1/jobs/createTask` body `{ model, input }` (follow the docs: `input` may need to be an object or a JSON string — support both via `KIE_INPUT_AS_STRING=1`); poll `GET /api/v1/jobs/recordInfo?taskId=…` every 3 s until `data.state` is `success` or `fail`; on success parse `data.resultJson` (JSON string) → `resultUrls[0]`. Errors come back as HTTP 200 with a non-200 `code` — check `code`. Respect the 20 requests / 10 s limit (max 4 concurrent), retry 429 with backoff, resume (skip ids already downloaded), `--only id1,id2`, `--dry-run` (print prompts and estimated count).
  - Download immediately (kie keeps files 14 days), convert to WebP 768×768 (quality ~80) into `app/img/ex/<id>-start.webp` and `<id>-finish.webp`. Use `sharp` as a devDependency in `scripts/package.json` (not in the app). Log credits consumed (`data.creditsConsumed`).
- `scripts/illustrations/review.html` + `review.mjs` (local server): grid of every generated pair with Approve / Regenerate / Reject; writes `app/data/illustrations.json` `{ "<id>": { "start": "img/ex/<id>-start.webp", "finish": "img/ex/<id>-finish.webp", "source": "ai", "model": "…", "created": "…" } }` containing only approved ids; "Regenerate" appends the id to a queue file the generator can run with `--queue`.
- App: if an exercise has an approved illustration, the exercise sheet shows it first: Start and Finish images side by side (tap to crossfade between them, auto-alternate every 1 s like a GIF) with the red arrows from Part A overlaid optionally; toggle to the animated figure. Lists may use the start image as thumbnail. Lazy-load and add viewed images to the offline cache (not to SHELL, to keep install size small). Fallback is always the Part A figure.
- Credits page / THIRD_PARTY_NOTICES: note "ภาพประกอบบางท่าสร้างด้วย AI (kie.ai, model …)"; README section "Generating illustrations" with exact commands, e.g.
  `cd scripts && npm i && KIE_API_KEY=... node illustrations/generate.mjs --dry-run`.
- Do not generate any images yourself and do not commit any images in this round.
